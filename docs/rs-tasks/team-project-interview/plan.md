# План: командный проект и интервью

Вариант 1 README: простой онлайн-магазин. Спека: [spec.md](./spec.md).

Код, репозиторий, коммит и пуш не начинать, пока Дмитрий не утвердит план. Дальше один шаг за раз. Коммит и пуш шага только после отдельного «можно коммитить». Сообщение коммита на английском, в повелительном наклонении. Спеку и план в репозиторий задания не класть.

Общий репозиторий `Bogagree/team-store`, публичный, ветка `main`. Это не форк школы. Имя можно сменить до шага 1, если пара договорится иначе. Напарник — collaborator. Его логин в плане не подставлен: его ещё нет в документации.

Каждый шаг с кодом приложения: одна ветка `feature/<имя>`, один коммит, после согласия Дмитрия — PR в `main`. Напарник оставляет отзыв, затем PR мержат. Карточку на доске двигают: «В работе» → «На ревью» → «Готово». Ветку сдачи не мержить.

Разделение, чтобы на записи у каждого был свой вклад:

- Дмитрий: каркас, страница «О нас», удаление из корзины и сумма, тесты функции суммы, деплой, своя запись кандидата, свой PR сдачи.
- Напарник: список товаров, добавление в корзину, запись где кандидат — он, свой PR сдачи. Эти шаги агент за Дмитрия не коммитит.
- Ревью взаимное: Дмитрий смотрит PR напарника, напарник смотрит PR Дмитрия.

Функция для интервью: общая стоимость корзины. На записи Дмитрий дописывает новые тесты к уже закоммиченным, старые не удаляет.

## 1. Репозиторий и каркас

Делает Дмитрий.

Появится публичный репозиторий и запускаемое приложение Vite `vanilla-ts` с Vitest. На `main` достаточно стартового README. Каркас — один коммит в `feature/scaffold`. В README одна фраза, что это простой онлайн-магазин к заданию, и ссылка на README задания. Скрипт `test` на этом шаге: `vitest run --passWithNoTests`. `node_modules` и `dist` в git не попадают, `package-lock.json` попадает. Пример `counter` из шаблона Vite в коммит не входит.

Файлы: `README.md`, `.gitignore`, `package.json`, `package-lock.json`, `tsconfig.json`, `vite.config.ts`, `index.html`, `src/main.ts`, `src/style.css`, `src/vite-env.d.ts`. Точный набор шаблона `vanilla-ts` можно дополнить тем, что создаст `npm create vite@latest -- --template vanilla-ts`.

Проверка: `npm ci`, `npm run build`, `npm test` завершаются без ошибки. `npm run dev` открывает стартовую страницу Vite. В репозитории нет секретов.

Сообщение коммита: `feat: add vite typescript scaffold`

## 2. Напарник и доска

Делает Дмитрий, когда известен логин напарника. Регистрация на сайте поиска напарника — действие Дмитрия до коммита, в репозиторий она не пишется.

Появится приглашение collaborator, доска GitHub Projects со статусами «Запланировано», «В работе», «На ревью», «Готово», задачи на следующие шаги с ответственными, и ссылка на доску в README. Напарнику нужен доступ и к репозиторию, и к доске: гайд напоминает, что это разные настройки.

Файлы: `README.md`.

Проверка: напарник открывает репозиторий и доску и может двигать карточку. В README есть ссылка на доску. У каждой задачи шагов 3–9 есть ответственный.

Сообщение коммита: `docs: document the task board and partner`

## 3. Страница «О нас»

Делает Дмитрий. Ветка `feature/about`.

Появится стартовый экран при загрузке: что делает магазин, Дмитрий и напарник (имя или логин), краткая формулировка закреплённой за каждым задачи с доски. С этого экрана есть переход к списку и к корзине и возврат назад. Список и корзина на этом шаге могут быть пустыми блоками. Переключение разделов на одной странице, без отдельной библиотеки маршрутов.

Файлы: `index.html`, `src/main.ts`, `src/style.css`.

Проверка: `npm run dev`, обновить страницу. Первым виден блок «О нас», оба участника на месте, ссылки переключают разделы и возвращают на «О нас». `npm run build` проходит.

Сообщение коммита: `feat: add the about page`

## 4. Список товаров

Делает напарник. Ветка `feature/catalog`. Агент этот коммит не создаёт.

Появится файл с товарами в проекте и экран списка. У товара есть уникальный `id`, название и цена. Товаров несколько, чтобы сумма из двух цен отличалась от одной. Тема и названия — как договорится пара.

Файлы: `src/products.ts`, `src/main.ts`.

Проверка: в списке видны все товары из файла, у каждого название и цена. В коде нет запроса к внешнему API. После `git pull` у Дмитрия тот же список.

Сообщение коммита: `feat: add the product catalog`

## 5. Добавление в корзину

Делает напарник. Ветка `feature/add-to-cart`. Агент этот коммит не создаёт.

Появится действие «в корзину»: товар виден в разделе корзины. Повторное добавление того же `id` вторую строку не создаёт и состав корзины не меняет. Сохранение корзины после перезагрузки не делается.

Файлы: `src/cart.ts`, `src/main.ts`.

Проверка: добавить товар — строка появляется в корзине. Нажать ещё раз — строка одна. Добавить другой товар — строк две. Перезагрузка может очистить корзину: это не ошибка шага.

Сообщение коммита: `feat: add products to the cart`

## 6. Удаление и общая стоимость

Делает Дмитрий. Ветка `feature/cart-total`.

Появится удаление строки из корзины и общая стоимость. Сумму считает чистая функция: на вход текущие строки с ценой, на выход число. Экран берёт сумму только из неё. Пустая корзина показывает 0.

Файлы: `src/cart.ts`, `src/main.ts`.

Проверка: удаление убирает строку, сумма уменьшается на цену этого товара. Удалить все — сумма 0. Сумма на экране совпадает с ручным сложением цен строк. `npm run build` проходит.

Сообщение коммита: `feat: add cart removal and total`

## 7. Тесты функции суммы

Делает Дмитрий. Ветка `feature/cart-tests`.

Появится набор unit-тестов на функцию суммы, и `npm test` будет запускать их без `--passWithNoTests`. В коммит входят сценарии: пустая корзина даёт 0; один товар даёт его цену; несколько товаров дают сумму цен; порядок строк сумму не меняет. Сценарий с ценой 0 в коммит не входит: его Дмитрий пишет на записи.

Файлы: `src/cart.test.ts`, `package.json`. Если шаблон не подхватит тесты сам, правка `vite.config.ts` входит в этот же коммит.

Проверка: `npm test` проходит и в выводе есть эти тесты. Сломанное ожидание роняет команду. `npm run build` проходит.

Сообщение коммита: `test: add cart total tests`

## 8. Фактический вклад на «О нас»

Делает Дмитрий после слияния шагов 4–7. Ветка `feature/about-contributions`.

Появится текст вклада, который совпадает с уже смерженными задачами, а не с предварительной формулировкой шага 3. У Дмитрия: «О нас», удаление, сумма, тесты, и деплой, если шаг 9 уже будет влит к моменту записи; до деплоя про деплой на странице не писать. У напарника: список товаров и добавление в корзину.

Файлы: `src/main.ts`.

Проверка: на стартовом экране оба участника и вклад каждого. Формулировки совпадают с закрытыми карточками доски. `npm run dev` и `npm run build` проходят.

Сообщение коммита: `feat: update team contributions`

## 9. Деплой

Делает Дмитрий. Ветка `feature/deploy`.

Появится опубликованное приложение GitHub Pages. Для сайта вида `https://bogagree.github.io/team-store/` в Vite задаётся `base` `/team-store/`. Workflow публикации отдельный от проверок, по руководству Vite для GitHub Pages. Источник Pages — GitHub Actions.

Файлы: `vite.config.ts`, `.github/workflows/pages.yml`.

Проверка: после слияния в `main` workflow в Actions завершается успешно. Ссылка открывается в инкогнито без входа. Видны «О нас», список, добавление, удаление и сумма. Повторное добавление того же товара по-прежнему не дублирует строку.

Сообщение коммита: `ci: deploy the app to github pages`

## 10. Интервью и файл сдачи

Делает Дмитрий. Один коммит в ветке `submission/bogagree`, созданной от `main` после шагов 1–9. Этот PR не мержить.

Сначала запись 15–30 минут, где Дмитрий — кандидат. На ней есть знакомство, показ приложения, доски и репозитория, личный вклад, распределение задач и ревью, несколько вопросов из спеки с конкретным примером решения, затем live coding по функции суммы: новые тесты пишутся на записи (сценарий с ценой 0 или другой ещё не закоммиченный), `npm test` запускается, результат разбирается. В тот же период напарник проводит свою запись, где кандидат — он, и готовит свой файл и свой PR. Чужой PR агент не открывает.

После записи в коммите появляется `submissions/Bogagree.md`: оба участника, что делает магазин, задачи Дмитрия, ссылка на деплой, репозиторий, доску и на видео, где Дмитрий кандидат.

Файлы: `submissions/Bogagree.md`.

Проверка: файл содержит все четыре группы сведений из README. Ссылка на видео в инкогнито открывается без входа и без запроса доступа, оба голоса слышны, экран читается. После согласия Дмитрия открыть PR в `main`: в описании те же сведения и те же ссылки. PR остаётся открытым.

Сообщение коммита: `docs: add bogagree submission notes`

## 11. Самопроверка по критериям README

Делает Дмитрий. Submit в RS App не нажимать.

Новых возможностей этот шаг не добавляет. Пройти список. Если чего-то нет на записи или в ссылках, шаг не закрывать: недостающее дописать в записи или поправить одним коммитом в `submission/bogagree`. Если всё на месте, коммита нет.

- PR открыт в `main` и не смержен.
